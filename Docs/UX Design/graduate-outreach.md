# UX Brief: Graduate outreach

**Job:** A training and relationship-building exercise that a person with fifty
doors and one shot at each can actually run — without ever reading as a pitch.

**Lives on:** Today, People, the composer and approval queue, Send controls,
Proof. Plus one new surface: the coordinator view.

---

## 1. The ask

**Job:** Every message the product writes is a request to learn or to meet.
Never an offer.

### How it works

1. A plan declares its purpose when it is created — *assessment*, *experience*,
   *a role*. There is no default and no mixed plan.
2. The composer writes under the honesty rules plus one more: no offer, no price,
   no service.
3. The guardrail runs before the draft reaches the queue. A draft that offers,
   prices or promotes a service is rewritten once; if it still trips, it goes to
   the human with the offending sentence marked.
4. A plan whose purpose is commercial keeps the visible unsubscribe footer and
   the full compliance load. No toggle, no per-message override.

### Hard rules

- Purpose lives on the plan, not the message.
- The guardrail blocks. It does not warn.
- The user never meets compliance vocabulary. They read *"this reads like a
  pitch"*, not *"CEM classification failed"*.

---

## 2. Today

**Job:** One sentence, one button, one number — and the number is how many doors
are left.

### How it works

1. On the first plan, count the addressable list and say it. *"Fifty-two
   employers match. That's the whole game."*
2. The number counts down as targets are spent. It never counts up.
3. If there is a date — assessment due, program window, visa — work backwards
   from it and say whether the arithmetic fits.
4. One next action underneath: approve one email, or send one LinkedIn message.

### Hard rules

- No rates, no percentages, no grading. Ever.
- The number is targets remaining, not emails sent. Sent is not progress.
- A deadline that does not fit is said in week one, plainly, once, with the one
  thing that would make it fit.

---

## 3. People and the router

**Job:** Who can open this door.

### How it works

1. A target is chosen. The router ranks routes to them by tie strength.
2. Every route names a person and its provenance — *"same cohort, 2024"*,
   *"your coach knows them"*, *"worked there 2019"*.
3. Cold sits last, present, and honestly labelled.
4. Choosing a route spends the target — whether or not it lands.

### Hard rules

- Warm before cold by ordering, never by a gate. A visa clock does not wait.
- Provenance always shows. A tie without provenance is not a tie.
- An empty router is a seeding failure, not a user failure. Never answer it with
  a blank page and a search box.

---

## 4. Send controls, reshaped

**Job:** Protect the target, not the mailbox.

### How it works

1. The lever the screen leads with is per-target: how many touches this person
   and this company may ever receive, across every channel and every plan.
2. Two touches per target. Daily caps still exist and are no longer the thing
   the user thinks about.
3. Cohort caps sit above the workspace. The student sees *"someone on your course
   is already approaching them"* and the next route — never a number, never a name.

### Hard rules

- Per-target budget is the headline; the daily allowance moves below the fold.
- A cohort collision explains itself in one sentence and offers the next route.
  It never simply refuses.
- No student ever sees another student's activity.

---

## 5. Proof

**Job:** The artefact, or the record — the ask decides which.

### How it works

1. *Assessment and experience* → signed agreements, named businesses, dated
   outcomes. Portable, exportable, theirs.
2. *A role* → who was spoken to, what came of it, what is still live. Read on
   screen, not exported. The outcome is the job; there is no artefact.

### Hard rules

- Nothing on this screen is a rate.
- No conversion prompt, no "turn this into a client" button. The product stops
  at the relationship and the human carries it from there.

---

## 6. Coordinator view

**Job:** Stop a cohort saturating a town.

### How it works

1. Employers approached, by how many students, inside what window.
2. Heat, not names — a coordinator sees that an employer is at capacity.
3. They can cap or exclude an employer for the whole cohort.

### Hard rules

- Coverage only. Never per-student performance, never a leaderboard.
- No student is identifiable anywhere in the view.
- This surface must not become the grading screen graduate mode forbids.

---

## Do not build

- Open rate, anywhere. The pixel is gone.
- A visible unsubscribe footer on a non-commercial send.
- A score against a named person. Score the employer and the role.
- Any screen that grades the user.
- A pitch composer, an upsell step, a convert-to-client flow.
- Warm-up UI of any kind.
