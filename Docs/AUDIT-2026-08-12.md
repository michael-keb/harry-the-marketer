## LAUNCH BLOCKERS (fix before real leads)

1. **Bounce brake is decorative — no automated bounce feed.** `bounceStats`/`brakeReason`
   (gates.js:428-463) key on `leads.status='bounced'` / `messages.send_status='bounced'`, but
   nothing ever sets those automatically — no MAILER-DAEMON parsing, no provider webhook, no
   upkeep job. The flagship safety brake, the `/send-health` screen, and warm-up auto-adjust
   never react to real bounces. Single most important gap for autonomous cold email.

2. **Transient failures strand leads permanently; no retry.** Any Gmail 5xx/429 or Twilio blip
   sets `state='error'` (engine.js:1265-1268), a state the tick never re-selects. SMS daily-cap
   exhaustion does the same (channels/send.js:72-74). Plus SMS is gated by the *email* mailbox's
   cap, not its own (engine.js:651-656). On a 20s autonomous engine, blips become silent stalls.

3. **`at HH:MM` / `window` clocks in the past fire immediately** (verified by execution).
   step-timing.js:200-232 never rolls forward: `after 2h at 09:00` computed at 14:00 returns
   09:00 *today* and sends now, outside the declared window. Affects waits, timeout edges, and
   the campaign-level random window.

4. **No-reply edge can fire days early.** When the frozen `wait_until` elapses, `pickNoReplyEdge`
   prefers the switch-channel edge regardless of its authored delay (engine.js:154-160,1163-1181).
   A node with `no reply 3d → email` and `no reply 7d → SMS` fires the **7-day SMS edge at day 3**.
   (Default config is email→sms, so this is the common case.)

5. **No per-lead send ceiling + cross-tick loops send forever.** `MAX_HOPS_PER_TICK` only stops
   same-tick `always` cycles; a `no reply` cycle (F→G→F) emails across ticks indefinitely, and the
   person-frequency cap exempts everything after the first touch. No max-sends / max-days per lead
   anywhere. The DSL plan flagged this as "a live bug"; still live.

6. **Replies lost if a mailbox is down >3 days.** `gmailRecentInbound` uses `newer_than:3d`,
   `maxResults:20`, and never reads `nextPageToken` or a watermark (google.js:222-255,
   upkeep.js:509-524). If the app/mailbox is offline >3 days, every reply in the gap is
   permanently unreachable. High-volume mailboxes also lose the oldest replies each 5-min sweep.

7. **`reply` events never fire for active campaign leads.** The per-thread engine path
   (`syncInbound`, mailer.js:228-256) inserts the reply but never `logEvent('reply', …)`; only the
   5-min sweep does. Since the engine path wins for active leads, `LEAD_REPLIED` webhooks and the
   activity trail silently miss the replies customers most care about.

8. **Rate limiter is broken two ways.** (a) The `/track` limiter is mounted with no path
   (index.js:74), so *every* request — API, SPA, assets — hits the 300/min-per-IP tracking bucket
   first; an office behind one NAT gets 429s. (b) The `/api` limiter keys on the *unverified*
   session cookie before auth (index.js:87-93), so a forged random cookie per request defeats the
   600/min ceiling entirely and grows the bucket map. Key on verified session, fall back to IP.

9. **Compose runs before the gate — pays for AI every 20s while blocked.** Ungated workspaces
   compose *before* `resolveSend` (engine.js:799-858); a blocked slot discards and re-composes each
   tick — a paid model call every 20s per blocked lead, all night. Plus `researchLead` runs a
   web-search agent per lead with no budget/meter (PRODUCT.md marks the spend cap "blocking").

10. **No `unhandledRejection` handler.** On Node 22 an unhandled rejection exits the process. The
    tick is well-guarded, but floating promises (`syncSheetsQuietly()` engine.js:1308,
    `void fireWebhooks()` index.js:156) are only safe by current invariant; one regression crashes
    the whole API server. A 3-line handler converts a crash into a log line.

## SECURITY

- **Webhook SSRF (multiple bypasses).** The guard checks only the URL string:
  - IPv4-mapped IPv6 literal `[::ffff:169.254.169.254]` serialises to hex and evades the
    dotted-quad regex → allowed (webhooks.js:160-179, verified).
  - Redirects are followed with no re-check; a public host can 302 to `169.254.169.254`, and the
    internal response body is echoed back to the user (blind SSRF → read primitive) (webhooks.js:386-407).
  - No DNS resolution, so a public hostname with an internal A record (or rebinding) passes save-time
    and every re-check.
- **Webhook CRUD has no role gate** (webhooks.js:629). Any workspace *member* can subscribe a
  workspace-wide `reply` webhook to an external host; reply events carry the first 120 chars of the
  inbound email → silent reply-content exfiltration.
- **Dev-login is a soft-gated prod takeover.** If Auth0 is unset or `DEV_LOGIN=1` leaks, `POST
  /api/auth/dev-login` signs anyone in as any email and merges into that email's workspace
  (auth.js:235-249). It's a *warning* in prod unless `PRODUCTION_STRICT=1`. Make it refuse outright
  when `NODE_ENV=production`.
- **Secrets at rest are plaintext.** OAuth refresh/access tokens and Twilio auth tokens live
  unencrypted in SQLite; `scripts/backup-db.mjs` copies them (plus all lead PII and message bodies)
  into the backup dir, retained 14 days. No at-rest encryption anywhere.
- **Forward puts BCC recipients in the To: header** (inbox.js:1287). `gmailSend` supports proper
  cc/bcc but the forward call flattens `[to,...cc,...bcc]` into `To:`; a blind-copied manager is
  exposed to the recipient. The DB records it as bcc while the wire says otherwise. (Reply path does
  it correctly.)
- **Sessions have no revocation** — logout only clears the cookie; a stolen token is valid 7 days.
- **Cross-tenant write, unscoped** (inbox.js:1243-1245): the post-send `UPDATE messages … WHERE
  provider_message_id = ?` has no `user_id`; on an id collision it flips another workspace's row.
- **Ingest dedupe is global, not workspace-scoped** (db.js:450, upkeep.js:409). Two workspaces may
  legitimately connect the same Gmail account; the second silently drops every reply the first
  already saw.
- **`POST /api/inbox/sync` has no rate limit** — a logged-in loop can burn the workspace's Gmail
  quota and disable reply sync fleet-wide.

## API / PARITY MODULES — additional defects

Scoping discipline across the 16 parity modules is unusually good (every parameterised id runs
through `owned`/`ownedAll`, no SQL interpolates request values). The concrete exceptions:

- **Compliance: prospect fetch imports leads with no suppression check** (prospects.js:623-649,
  called from the fetch import at :1507). A blocked-domain or previously-unsubscribed address comes
  back from a provider fetch as an `active` lead. Every other importer checks (lists.js:506,
  campaigns.js:1717, routes.js:143). This can re-activate someone who opted out.
- **Second cross-tenant write** (campaigns.js:2826): `UPDATE messages SET manual_reply=1 WHERE
  provider_message_id=?` with no `user_id` (siblings at utilities.js:487 and inbox.js:1314 scope it).
  Outbound provider ids aren't unique/indexed, and an empty id (`''` default) can flag another
  tenant's rows + full-table-scans every manual reply.
- **Running campaign can lose its only sender** (campaigns.js:1631-1648): the "don't strand"
  guard reads only the `campaign_mailboxes` pool; a running campaign using just the legacy
  `campaigns.mailbox_id` has an empty pool, skips the 409, and gets `mailbox_id` nulled — the exact
  state the guard exists to prevent.
- **Prospect fetch can double-charge** (prospects.js:1422-1428): idempotency key is written *after*
  the upstream call, so two concurrent identical POSTs (double-click) both charge. senders.js:970
  does it correctly (reserve-before-call via unique index).
- **Mailbox test lies** (mailboxes.js:466-497, 916): `POST /mailboxes/:id/test` makes no network
  round trip — send/read legs are derived from stored status yet reported `checked:true` /
  "Ready to send". An unverifiable leg counts as a pass (:497 `c.ok || !c.checked`), so a Gmail
  mailbox that provably can't send still answers `ok:true`.
- **Schema migration drops constraints** (schema.js:718-742): `migrateOutlookProvider` rebuilds
  `mailboxes` from `PRAGMA table_info` alone, losing `user_id NOT NULL … ON DELETE CASCADE` and the
  `status` CHECK. After it runs, deleting a user orphans mailboxes instead of cascading, and status
  accepts any string.
- **Dead role check** (prospects.js:1725): guards on `req.wsRole === 'viewer'`, a value that can
  never occur (roles are owner/member/manager) — so every member can rename fetched lists.
- **Unbounded reads / leaking caches**: `replyOrigins` (analytics.js:521) selects every outbound
  message with no window predicate; module-level Maps `headlineCache`, `fetchIdempotency`,
  `TEST_SENDS`, `providerCache` never evict and grow for the process lifetime.
- Honest degradation confirmed elsewhere: providers/deliverability/prospects/senders are properly
  env-gated and return `configured:false` / `null` rather than faking data — good.

## REMEDIATION STATUS (branch `audit-fixes-2026-08-12`)

Fixed and verified in this pass. Suite after fixes: **server 1439 pass / 0 fail / 2 pre-existing
TODOs, web 116/116, build clean** (Node 22). Work was split across five Opus executor agents on
disjoint files plus direct fixes; every fix carries a test.

### Launch blockers — CLOSED
- **Bounce feed** — `server/mailer.js` `classifyBounce`/`markBounce` detect a DSN, resolve the
  failed lead, and set `leads.status='bounced'` + `messages.send_status='bounced'`; wired into both
  ingest paths (`upkeep.js` sweep + `mailer.js` per-thread). Transient 4.x.x defers are NOT
  suppressed (they'd kill a reachable lead). Tests: `tests/bounce-feed.test.js`.
- **Retry / terminal states** — `campaign_leads.retry_count`/`next_retry_at`, `mailboxes.needs_reconnect`;
  transient errors back off and retry, only permanent ones go terminal; Gmail/Outlook refresh
  distinguishes `invalid_grant` (reconnect) from transient 5xx.
- **Per-lead ceiling + loop guard** — lifetime `max_sends` (25) / `max_days` (120) finish a lead;
  cross-tick no-reply cycles bounded.
- **Step-timing past clocks** — `at`/`window` roll forward to the next occurrence; a delay-adjusted
  future day is no longer over-shifted (`tests/step-timing.test.js`).
- **pickNoReplyEdge early-fire** — a 7d SMS edge no longer fires at day 3.
- **Reply cursor/watermark** — `mailboxes.inbound_watermark` + `nextPageToken` paging; replies no
  longer lost after >3-day downtime.
- **reply event on engine path** — `LEAD_REPLIED` now fires for active-campaign replies.
- **Rate limiter** — tracking limiter scoped to `/t`; `/api` limiter keyed on the verified session
  with IP fallback (`tests/audit-security-fixes.test.js`).
- **Compose-after-gate** — the send gate is checked before composing; no paid AI call per blocked lead.
- **unhandledRejection/uncaughtException handlers** — a stray rejection logs instead of crashing.
- **Scheduled-send 'sending' reclaim** — user-facing (inbox route) + systemic (`upkeep.js`, 15-min
  grace); orphaned rows requeue instead of stranding (`tests/upkeep.test.js`).
